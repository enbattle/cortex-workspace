# Pilot 1 — toy repository, 2026-09-23

The first end-to-end run of cortex v2, before any real use. Every role that
cortex runs in a fresh context was a separate fresh agent; one agent played
the orchestrator and the human, and says so wherever it acted as the human.
The raw working notes are in `2026-09-23-toy-repo-raw-log.md`.

**Version:** this pilot ran on the first 2.0.0 revision (commit cd98457 and
its prose follow-ups), before spec Amendments 1 and 2. In particular the lock
then lived in `tasks.md`; the current flow (`lock.md` in its own commit) has
not yet been run by an agent.

**Repository:** `slugkit`, a tiny Node library (`slugify(input)`, 4 tests,
`node --test`). **Change:** add a `maxLength` option that truncates at a word
boundary, never mid-word, never leaving a trailing `-`.

**Limitation:** the toy repo's Claude Code subagent types (`.claude/agents/`)
aren't registered in the session that ran the pilot, so the adapter's
enforcement (reviewers without edit tools) was not exercised; fresh
general-purpose agents told to be read-only stood in for them. That still
needs a run from inside a real installed repository.

### The review's findings

1. **High:** `['a','b'].map(slugify)` now throws: `map` passes the index as
   `options`, which criterion 7's validation rejects. A break for existing
   callers that nobody weighed when the criterion was approved. Confirmed.
2. Low: `## Gate output` in `tasks.md` was empty.
3. Low: the change folder was committed after the test lock, so history
   can't show approval preceded locking.
4. Low: `design.md` had no `## As built` for a `lastIndexOf` deviation.

Finding 1 is a spec failure that review caught late, the case the operator
guide calls "promote recurring catches upstream"; see F11.

### Golden task

The obvious planted bugs (off-by-one at exactly `maxLength`, a trailing `-`)
were caught by the locked tests, which include a randomized comparison
against a reference, so the golden task uses a subtler one: a "performance"
commit that pre-cuts the raw input to `max(256, maxLength * 4)` characters,
which silently corrupts long inputs heavy in punctuation or non-Latin text
(`''` instead of `'hello-world'`). All 26 tests still pass. A fresh reviewer
named it at High with reproductions (27,437 mismatches in 200,000 random
cases). It did not repeat the main review's `.map` finding: two reviewers,
two different finding sets on nearly the same code, which is why
`docs/02-extensions.md` asks for each eval task to run more than once.
Saved as `evals/golden/review-maxlength/` (spec, planted diff, rubric).

## Friction, and what was done about it

**Must fix before real use**

| # | Evidence | Fix (in 2.0.0, before release) |
| --- | --- | --- |
| F1 | Editing the *pre-existing* `test/slugify.test.js` passed `tests-locked.sh`: only listed files were locked, so a regression test could be weakened unnoticed | `tests-locked.sh` locks every file matching `TEST_GLOBS` at the lock commit (spec amendment A1) |
| F2 | `node --test` also runs an untracked `test/helper.js`, which `TEST_GLOBS=*.test.js` didn't match | `INSTALL.md` asks what the runner *loads*, not how tests are named; config comment says the same |
