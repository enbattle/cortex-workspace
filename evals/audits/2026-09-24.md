## C. Merge readiness

Merging makes this what a HEAD install gets (see B2), so blocking means before merge.

**Blocking**

1. **High: a locked change can't be brought up to date with its base, and nothing says so.**
   - Reproduced: after the lock, `main` edits any file matching `TEST_GLOBS` (or `.cortex/config`), and the branch merges `main`. Result: `LOCK modified: test/b.test.js`. A rebase instead gives `LOCK moved` plus `LOCK bad-sha`.
   - There is no recovery. `lock.md` may be committed only once, so the change needs a new folder.
   - Two parallel changes that touch tests, or GitHub's "Require branches to be up to date", make the PR unmergeable. INSTALL 5b's settings list doesn't warn against it.
   - Fix: document the limit in INSTALL 5b, `test-first`/`implement` and CHANGELOG, with the recovery path. Better, have `tests-locked.sh` ignore locked-file changes that arrived through merges from the base (compare only first-parent commits after L), with a spec amendment and tests first.
2. **Medium: archiving a finished change fails CI.**
   - The template ships `changes/archive/`, and `docs/knowledge/index.md` points there, but no command says when to archive.
   - Reproduced: `git mv changes/a changes/archive/a` in a PR → `ci-gates: FAIL changes/archive/a` (`LOCK moved`), because the renamed `lock.md` matches `changes/*/lock.md`.
   - Fix: exclude `changes/archive/` in `ci-gates.sh`'s pathspec (add a test), and say in `retro.md` how to archive. Or drop the archive directory.
3. **Medium: docs.** Fix B1–B4 (suite count, release status, tag-based install, CI claims).

**Should fix, not blocking**

4. Record pilot 2 F5 in CHANGELOG "Still open", or waive it in writing.

6. INSTALL 5b: say that `ci-gates` runs the tests only for changes with a new or changed `lock.md`. A PR with no change folder gets only `check.sh`, so the test paths in CODEOWNERS (a `TODO(install)` that `check.sh` doesn't see) carry that case.
