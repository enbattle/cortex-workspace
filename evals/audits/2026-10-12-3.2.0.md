## Code findings (recorded, not blocking)

- **Low, uncertain.** `remove.sh`'s "kept as" extraction uses bash `=~`,
  which runs in the current locale; on a line with invalid UTF-8 next to
  `cortex/changes/...`, it might miss a match `grep -oE` found, and the
  "kept as" line would be missing (the reference itself is still listed).
- **Info.** `fp_split` sets the globals `FP_1`-`FP_3`, which `fp_drop`
  also overwrites; the one reader uses them immediately, so nothing breaks
  today; the file's header doesn't name them.
- **Info.** The remove suite's `cortex_seeded` cache doesn't check
  `merge_entries` or `commit_all`, so a failed build would be reused by
  every later case (test-only).

## Nominations (open, for the maintainer)

- **Merge:** the entry-rule pattern `^[[:space:]]*("[^"]*")` is now in
  three places (`entry_rule`, inlined in `entry_present`, and `adapt.sh`'s
  sed): one variable in `_footprint.sh` for all three (E4).
- **Merge:** a `fp_first` helper in place of the six
  `fp_match ... | sed -n 1p` calls, which would also make the lookups
  start no process at all.
- Closed: the first audit's nomination to delete the full-run
  demonstration half of the V4 planted test. The maintainer kept it
  (2026-10-12): it is the in-tree proof that the attack V4 defends against
  is real, so a later change undoing the lock step's order shows why it
  matters; its cost is a platform-dependent assertion count, recorded in
  the spec.
