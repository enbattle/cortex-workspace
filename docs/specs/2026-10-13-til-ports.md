# Plan: practices from `til` that cortex lacks (3.4.0)

Status: **approved by the maintainer, 2026-10-13** (written by the agent on
the maintainer's instruction, with D1-D3 answered as recorded below). A
point-in-time record.

## Context

On 2026-10-13 the maintainer asked which of `til`'s harness practices
cortex doesn't have, judged by R14 rather than by "it's a best practice"
(T1). `til` is the repository R12 credits and the 3.0.0 pilot ran in
(`evals/pilots/2026-10-09-rc-pilot-til.md`); by that date its pipeline log
had 236 rows, ten docs audits and three eval result logs. Most of its
practices are already here. Three gaps pass R14 now; two more (a docs
staleness audit, an independent read of retro edits) are left for a later
plan (Non-goals).

## Items

### P1. `check.sh` checks the pipeline log (C15)

**R14.**
- **Mechanism:** the log's header states rules (a row's format; a retro of
  `nothing to change` after failed gates or findings says why) that only
  an agent reading it enforces. R11: a rule a script can check, is.
- **Fit:** the pilot's R7: the retro row was written before the developer
  answered, then rewritten. `retro` step 5 now says to wait, in prose
  only. `til`'s `check-pipeline-log` rejects that row ("pending") and the
  bare `nothing to change`; it has run on every `til` change since
  2026-09-23.
- **Cost here:** one check in `check.sh`, its tests, one sentence in the
  log's header. No context cost: no agent loads it.
- **Reversibility:** delete the check and its tests.

**Behavior.** When `cortex/changes/pipeline-log.md` exists, C15 reads its
table: the first line starting with `|` is the header, the next the
separator, every later line starting with `|` a row. A cell boundary is a
`|` not preceded by `\`; cells are trimmed. C15 reports
`FAIL [C15] cortex/changes/pipeline-log.md: <message>` once per problem:

1. The header's cells are not exactly `Date`, `Change`, `Gate failures`,
   `Findings (H/M/L, pre)`, `Rounds`, `Retro`, `Escaped defect`.
2. A row hasn't exactly 7 cells.
3. A row's cells don't match, in order: `YYYY-MM-DD`; any non-empty text;
   a count at the start (`^[0-9]+`); `H/M/L` or `H/M/L, pre:N`
   (non-negative integers); a non-negative integer; non-empty text;
   anything.
4. A row's Retro contains the word `pending` (any case).
5. A row with a gate-failure count above 0, or any of H, M, L above 0,
   has a Retro that is only `nothing to change` (any case, ignoring
   surrounding spaces and trailing `.`).

Each message names the row by its first two cells and says which rule
it broke. A missing log is not a failure (C13 owns missing files). The
template's empty log passes. Runs on bash 3.2 and Git Bash; one `awk`
pass, no process per row (spec Amendment 7 of the v2 scripts).

Clarified by the test writer, within the rules above: the empty text
before a row's first `|` and after its last isn't a cell; a row that fails
rule 2 isn't also reported under rule 3; "the word `pending`" is a whole
word (`spending` passes); `, pre:N` takes a comma and a space; the header
is named by the path, not by cells.

The log's header gains one sentence: `check.sh` (C15) checks these
columns' format and the two Retro rules.

### P2. `test-first`: three gaps

**R14.**
- **Mechanism:** (a) `implement` can't edit a locked test, and `gates.sh`
  runs `LINT_CMD`, so a lint error in a new test costs a re-lock with the
  user's sign-off. (b) Step 3's "not ... an import error" contradicts a
  test of a module the design introduces, which can only fail by import.
  (c) A test removed or merged drops whatever only it asserted, and
  nothing asks what that was.
- **Fit:** (a) and (b) follow from the scripts and the text as written;
  `til`'s Stage 2 gate has both rules. (c): `til`'s 2026-10-13 friction
  aggregation, group 1: dropped coverage found a review round at a time
  (35 agents, 6 rounds over three changes). Here, the 2026-10-10 plan's
  N3 and N4 merged test cases on "assertion counts drop" alone.
- **Cost here:** about ten lines in `test-first.md`, one checklist item,
  one rule in this repository's `AGENTS.md`.
- **Reversibility:** text only.

**Changes.**
- **(a)** `test-first` step 3 also runs `LINT_CMD` and fixes any problem
  in the files it wrote before committing them: once locked, no later
  stage can. Step 7 (re-lock) does the same for its corrected files.
- **(b)** Step 3: a failure to import a module or name that the approved
  design introduces, and nothing implements yet, is the expected reason. A
  test that doesn't need that module goes in a file that doesn't import
  it, so its own reason shows.
- **(c)** A new step 2 paragraph: removing or merging an existing test,
  for each behavior only it asserted, names a code change that breaks
  that behavior and shows a remaining test that fails on it (the change
  made in a scratch copy outside the repository). A test removed with the
  behavior it tested needs none. The result goes under
  `## Criteria to tests` in `tasks.md`, so review reads it.
- The review checklist's Tests section gains: "A removed or merged test
  has its mutation evidence in `tasks.md`; a behavior no remaining test
  guards is Medium."
- This repository's `AGENTS.md`: a change that removes or merges test
  cases gives the same evidence in its commit message, beside the
  assertion-count change it already states.

### P3. A golden task for `implement`'s triage

**R14.**
- **Mechanism:** 3.3.0 rewrote `implement` step 1 (checking findings
  against recorded decisions), and nothing measures it: the golden task
  covers `review` only. A triage that fixes an already-decided finding
  undoes the decision; one that drops a real finding ships the defect.
- **Fit:** the 3.3.0 spec's own Non-goals note the split is unmeasured;
  `til` measures its triager (feature-review FR-06, FR-07), and its 2026-10-01
  run found one scenario's finding unreachable by construction.
- **Cost here:** a directory of markdown and a run when step 1 changes.
  No script, no new fixture: it reuses `review-maxlength/fixture.bundle`,
  whose source the refresh keeps frozen.
- **Reversibility:** delete the directory and the trigger line.

**Contents.** `evals/golden/triage-maxlength/`:
- `README.md`: the procedure. A fresh clone at `golden-planted`, as the
  review task's step 1; then the procedure writes `findings.md` into the
  change folder as `review-findings.md` and commits it alone. A fresh
  agent gets: read and execute `implement.md` step 1 only for that
  folder, read-only, returning one outcome and reason per finding. Run
  twice.
- `findings.md`: one `## Round 1` request-changes round, three findings:
  - **T1, real:** the plant (the input pre-slice; the rubric's
    reproductions). Expected: **fix** or **fix via test-first**.
  - **T2, already decided:** "`titles.map(slugify)` now throws; breaks
    existing callers (E2)", rated High. Expected: **disputed**, naming
    AC8 or the proposal's Open question 6.
  - **T3, not real:** a claim that doesn't reproduce at that tag (a
    concrete input the code handles correctly, chosen and checked when
    the file is written). Expected: per decision D2 below.
- `rubric.md`: the grades. PASS per run only if all three match; the
  reason must cite evidence (a reproduction, or the decision's location).
- `results/<date>.md`.

This repository's `AGENTS.md`: after editing `implement.md` step 1, run
this task twice with fresh agents and record the result, as for review.

### As built (P1)

1. A message states the broken rule in words, not its number.

## Decisions (the maintainer's answers, 2026-10-13)

- **D1. C15 applies to every row**, not only rows after a date.
  Decided: every row. README says cortex has no real install yet (the pilot's was
  removed), so no existing log can start failing. The alternative (`til`'s
  dated exemptions) adds a constant for rows that don't exist.
- **D2. A finding that doesn't reproduce or isn't reachable.** `implement`
  step 1 asks for that evidence, but its four outcomes (fix, fix via
  test-first, known limitation, disputed) define disputed only as "would
  contradict a recorded decision", so an unreal finding has no defined
  outcome. Decided: it is **disputed**, with the attempt as evidence
  (the command and its output), and stops for the user. This keeps the
  rule that the implementer, biased toward rejecting, never closes a
  finding alone (R14). The alternative, a fifth outcome **rejected** with
  quoted evidence (as `til`'s orchestrator may), lets the author close
  its own findings. Either way, one sentence in `implement` step 1, and
  T3's expected outcome follows it.
- **D3. Where the suites run.** There is no Linux environment on this
  machine (WSL has only `docker-desktop`; the Docker engine isn't
  running). Options: start Docker Desktop and run the suites in an
  `ubuntu` container, or push the branch and let CI run them (the test
  writer confirms its tests fail on CI). Either needs the maintainer: the
  first to start Docker, the second a go-ahead to push. Decided: push the
  branch and let CI run them (CI runs on pull requests, so as a draft pull
  request).
